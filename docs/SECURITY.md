# Security and trust boundaries

- **Inputs:** two distinct commit-pinned raw GitHub `.txt` URLs; lowercase SHA-256; 30–50,000 bytes per document; title 3–160 characters; page size 1–20. Only the creator requests reviews. No payments, custody, scoring of researchers or author authority claims.
- **Evidence:** validators independently verify HTTP 2xx, exact byte count, SHA-256 and valid UTF-8 before inference. URL restrictions exclude mutable branches, URL query tricks and private-network hosts. The HTTP client downloads the response before the byte check; this is a post-fetch bound, not a streaming network cap.
- **Snapshot authenticity:** submitter-controlled GitHub content is a version commitment, not proof of official publication, preregistration timing, faithful extraction or source completeness. These are explicit human review responsibilities. URLs/dates in the content remain unverified assertions. No PDF parsing or automatic registry import is claimed.
- **Prompt injection:** source documents are serialized as untrusted JSON data, with explicit instructions to reject embedded commands and use insufficient-evidence findings. Exact excerpt validation and independent judgment reduce risk, but do not eliminate model prompt-injection risk.
- **Consensus:** custom validator reruns retrieval/inference; exact category classification equality prevents a matching top-level verdict from hiding different findings. A second source-grounded check validates the leader's explanations. Model failures become INCONCLUSIVE, not ALIGNED. If validators disagree, the network's transaction lifecycle controls retries; the app shows only finalized state.
- **History:** record commitment and each decision hash use canonical sorted UTF-8 JSON. Each attempt binds the original record commitment and previous hash. Browser exports verify the chain; that checks receipt consistency, not a cryptographic proof that the RPC itself is honest. Reads come from the configured Studionet endpoint.
- **Recovery:** each record has three creator-controlled completed attempts. No single challenge slot exists and other wallets cannot consume attempts. Independent records remain available to other reviewers. After an inconclusive review, retries preserve the original decision rather than replacing it.
- **Frontend:** chain and endpoint fixed to Studionet; no account or signing secrets; all evidence is rendered through textContent, never injected HTML; failed reads clear stale results. The Studio route is a real separate signing flow, not a wallet connection embedded in this site.

Report security issues through the repository's issue tracker without including secrets or private study data.
